# Versions

Repo version lives in `.claude-plugin/plugin.json` and `marketplace.json`. Bump the middle number for a new skill, the last number for changes to an existing skill, the first for restructures. Each skill carries its own `metadata.version` in its frontmatter and must be bumped on any shipped change, since that is what installed users compare against.

## 1.5.0 (2026-09-11)

The analysis, and a rewrite for the person reading the answer.

New data

- Every analysis script now reads the analysis through one shared scope in `analysis/frame.py`, so all ten skills measure the same population: campaigns of 1,000 Entrants or more, with crypto, ambiguous and purchase-only campaigns removed. `the analysis notes` documents the tables, the known gaps and where each script stands.
- Findings mined across eight domains: prize economics, method combinations, structure thresholds, campaign goal and asset yield, vertical profiles, organizer history, success profiles and traffic quality. Roughly 38 tested relationships were dropped because they did not survive a control, and the ones that lived are named with what they cannot show.
- Templates from the analysis link a campaign to what it was built from, so a review can compare against others from the same template or source kind.

Written for a marketer

- Findings lead in words and hand their figures to a table underneath. Prose paragraphs carrying five or more figures went from roughly fifty to eight.
- A rate is a percentage or a count per 100 Entrants, never a raw decimal a reader has to divide. Sample sizes sit in brackets or the Source line, out of the sentence.
- Gleam's own words arrive with the app's capitals, in the prose and in the scripts' own output: Impressions, Actions, Entries, Conversion Rate, Entry Method, Entrant, Prize, Winner.
- A finding is never a ban. Where a mechanic scores lower on average the answer prices it, says what it buys, and leaves the choice with the reader.

Fixes

- Eighteen Gleam doc URLs were broken by the capitalisation pass, so `/setup/prizes` had become `/setup/Prizes`. A capital inside a URL now fails the linter.
- Answers were printing "extracted", our word for a figure computed from the export. Gone from the instructions, and the checker treats it as jargon.
- `review.py`'s `--history` help named capitalised columns its own parser could not read, so a user's file would have parsed as empty. The parser takes either case, held by a self-test.
- Reference tables printed the export's own labels, so a reader met "fashion_beauty" and "Follow_x".
- Winner communications assumed a reserve Winner already existed in every edge case, leaving anyone who drew one name with nowhere to go.

Checks

- `evals/style_check.py` grew from 10 detectors to 33, with fixtures and a self-test wired into CI, and three false positives removed where it was failing answers for obeying their own skill.
- `scripts/style_lint.py` gained the capital-inside-a-URL rule and flags two rates under one in the same sentence.
- One fresh reader answered a realistic message for each of the ten skills, seeing only that skill's folder. All ten pass, and each `evals/cases.md` records what the answer got right.
